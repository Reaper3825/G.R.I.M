  4. WILL IT FIX THE ACTUAL PROBLEMS?
──────────────────────────────────────────────────────────────────────────────

  Problem 1: Token 36 collapse (33% argmax dominance, should be ~0.04%)
  ─────────────────────────────────────────────────────
  Token 36 collapse is a WEIGHT NORM problem, not a hidden cosine problem:
    • tok36 W_rms = 0.0446 vs content tokens ~0.030 (1.49× larger)
    • Logit = h · W[v]^T = h_rms × W_rms × cos(h,W[v]) × d_model
    • Token 36 wins argmax because its weight vector is bigger, NOT because
      hidden states are too similar.
    
  Cosine reg forces hidden states apart, but the SAME weight vector (W[36])
  still produces the highest logit regardless of hidden state diversity.

  Prediction: Cosine reg will NOT fix token 36 collapse.

  Problem 2: Loss plateau at ~3.73-3.86
  ─────────────────────────────────────────
  The loss is determined by:
    L = -log(p_target) = -log(softmax(h · W[target]^T))

  Making hidden states more orthogonal:
    • Slightly increases variance of logits across positions (good in theory)
    • But doesn't change the fundamental issue: W[36] is too large

  At λ=0.1, the reg adds 0.01% to loss. The gradient feedback is ~0.56× of
  the main signal but flows through the ENCODER (attn/ffn/rmsnorm), not the
  embedding/LM head where the real imbalance lives.

  Prediction: Cosine reg will NOT break the loss plateau.

──────────────────────────────────────────────────────────────────────────────
  6. IMPLEMENTATION COST vs BENEFIT
──────────────────────────────────────────────────────────────────────────────

  COST:
  • New CUDA kernel: pairwise cos(h_i, h_j) forward + backward for all T²/2 pairs
  • Memory: O(T²) pairwise similarities or O(T·d) for gradient accumulation
  • Compute: T=1024 → 524,288 pairs × 768 dim = ~400M FLOPs per batch
  • Autograd integration: new GradFn node, chain through encoder backward
  • Risk: λ tuning — too high destroys task signal, too low does nothing

  BENEFIT:
  • E[cos²] reduced from 2.8× to ~2× above random
  • Token 36 collapse: unchanged
  • Loss: unchanged
  • Quality of hidden representations: marginal improvement

  VERDICT: NOT WORTH IMPLEMENTING.
  
  The hidden cosine values are already healthy (avg|cos| ≈ 0.05 vs 0.036
  random baseline). The collapse problem is NOT caused by hidden state
  similarity — it's caused by W[36] weight norm dominance (0.0446 vs 0.030).

──────────────────────────────────────────────────────────────────────────────
  7. WHAT WOULD ACTUALLY HELP INSTEAD
──────────────────────────────────────────────────────────────────────────────

  The token 36 / loss plateau problem is downstream of hidden states:

  (a) Weight norm regularization on LM head: λ · ||W[v]||²
      → Directly penalizes tok36's outsized W_rms (0.0446 → ~0.030)
      → Equalizes logit scale across tokens

  (b) Max-entropy logit regularization: λ · (-H(softmax(logits)))
      → Directly penalizes argmax concentration
      → Would reduce 33% → closer to uniform

  (c) Per-row weight decay on LM head (already partially via AdamW):
      → Check if w_decay applies to lm_head weights
      → If tied embeddings, the embedding learning rate may be pulling
        W[36] larger while AdamW decay is too weak

  These target the actual problem (W[36] norm) rather than the symptom
  (hidden state similarity, which is already healthy).
