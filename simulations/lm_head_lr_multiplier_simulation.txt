3. WHAT lr_multiplier DOES (MECHANICALLY)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Current AdamW kernel (line 59 of AdamW_Kernal_GPU.cu):

    params[i] = param - learning_rate * (adam_update + weight_decay * param)

  With lr_multiplier μ per ParameterGroup:

    effective_lr = learning_rate * μ
    params[i] = param - effective_lr * (adam_update + weight_decay * param)

  This scales BOTH the Adam step AND the weight decay step by μ.

  Critically, lr_multiplier does NOT affect:
    - The gradient computation (forward + backward pass unchanged)
    - The backward signal flowing through the LM head into hidden states
    - The encoder's own update magnitudes
    - The m_state / v_state accumulation (moments track the raw gradients)

  What it DOES affect:
    - The parameter update: Δw = μ × lr × (m̂/(√v̂+ε) + wd × w)
    - For LM_HEAD type only. All other groups run at μ = 1.0

  This means:
    (a) The backward gradient ∂L/∂h[t] = (p - y) × W_lm^T is unchanged.
        The encoder receives the same learning signal regardless of μ.
    (b) The LM head's own weights change more slowly (by factor μ).
    (c) Since W_lm changes slower, p(v|t) evolves more slowly.
    (d) More stable p(v|t) → more stable gradients for all components.

5. WHY PREVENTING THE CROSSOVER MIGHT PREVENT COLLAPSE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  The collapse mechanism from logit_feedback_loop_simulation.txt (Section 2):

  1. At init, hidden states h[t] ≈ h̄ for all positions t (random, undifferentiated)
  2. LM head weight gradient for tok v:
       grad_W[v] = (1/N) Σ_t (p(v|t) - 1{y_t = v}) × h[t]
  3. With h[t] ≈ h̄:
       grad_W[v] ≈ (N × E[p(v)] - count_v) × h̄
  4. All the directional information is in h̄. The scalar coefficient
     (N × E[p(v)] - count_v) determines whether W[v] moves WITH or
     AGAINST h̄.
  5. For tok36 initially: E[p(36)] ≈ 1/V ≪ freq(36) = 10.7%
     → coefficient is NEGATIVE → W[36] moves TOWARD h̄ direction
     → this INCREASES logit(36) = h̄ · W[36]^T for ALL positions
  6. As p(36) rises, the coefficient shrinks. At p(36) = freq(36),
     the gradient is zero (equilibrium). BUT:
  7. Adam momentum (β1=0.9) carries W[36] past equilibrium.
     Once W[36] overshoots, p(36) > freq(36), and tok36 dominates argmax.

  The self-correction mechanism requires POSITION-SPECIFIC h[t]:
  - At positions where y_t = 36, the gradient wants p(36) → 1.0
  - At positions where y_t ≠ 36, the gradient wants p(36) → 0.0
  - These two competing forces balance ONLY if h[t] is different at
    target vs non-target positions.
  - If h[t] ≈ h̄, the two forces are collinear (both project onto h̄)
    and the net is just (E[p(36)] - freq(36)) × h̄ — no position info.

  THE TIMING RACE:
  ─────────────────
  The encoder (attn + ffn) differentiates h[t] by learning position-dependent
  patterns. The LM head aligns W[tok36] with h̄ (the mean direction).

  If the LM head finishes alignment BEFORE the encoder differentiates h[t]:
    → p(36|t) is high for ALL t (because h[t] ≈ h̄ and W[36] ∥ h̄)
    → argmax(logits) = tok36 everywhere → COLLAPSE
    → The gradient signal to the encoder becomes "reduce p(36) everywhere"
       instead of "learn position-specific predictions"
    → Degraded encoder learning signal → slower differentiation → STUCK

  If the encoder differentiates h[t] BEFORE the LM head fully aligns:
    → h[t] varies by position → logit(36|t) varies by position
    → p(36|t) is high only at positions where y_t = 36 (correct behavior)
    → No collapse. LM head then correctly learns conditional distributions.

  lr_multiplier directly controls this timing:
    μ < 1.0 → LM head alignment is slower → encoder gets more time
    μ > 1.0 → LM head alignment is faster → more likely to collapse

7. SECOND-ORDER EFFECTS OF SLOWING THE LM HEAD
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Effect 1: LM head stays near Xavier init longer
  ─────────────────────────────────────────────────

  Xavier-initialized W_lm has rms ≈ 0.024 (from wd_simulation.txt batch 2).
  At μ=1.0 batch 60, W_rms grows to approximately:
    W_growth = Σ(upd_rms over steps 1-30) ≈ 30 × avg(2e-6 to 1.3e-5) ≈ 2e-4
    W_rms(B60) ≈ 0.024 + order(2e-4) ≈ 0.024 (barely changed)

  Wait — the upd_rms (ABSOLUTE update magnitude) is tiny:
    Batch 10: lm upd_rms = 2.01e-06
    Batch 60: lm upd_rms = 1.27e-05
    Average over 30 steps: ~6e-06
    Cumulative: 30 × 6e-06 = 1.8e-04

  But W_rms starts at 0.024 and grows to 0.025 by batch 170 (wd_simulation).
  So the weight NORM barely changes. The collapse is about DIRECTION, not norm.

  With μ=0.5: cumulative W change is 0.5 × 1.8e-04 = 9e-05.
  The directional change is also halved. What matters is whether the encoder
  can diversify h[t] before even this reduced directional shift aligns W[36]
  with h̄.


  Effect 2: Backward gradient magnitude through W_lm
  ───────────────────────────────────────────────────

  ∂L/∂h[t] = (p - y) × W_lm^T

  Since ||W_lm|| barely changes in the first 80 batches (0.024 → ~0.025),
  the backward gradient magnitude to the encoder is essentially unchanged
  whether μ=1.0 or μ=0.5. The dominant factor is (p - y), not ||W_lm||.

  With μ < 1.0, p(v|t) stays closer to uniform for longer because the LM
  head weights change less. This means:
    p(v|t) ≈ 1/V for all v and t → (p - y) ≈ (-1 for target, +1/V for rest)
  The gradient is at MAXIMUM magnitude when predictions are uniform.

  As training progresses and p concentrates on frequent tokens:
    (p(36|t) - 0) = 0.3 for non-target → moderate positive gradient
    (p(36|t) - 1) = -0.7 for target → large negative gradient

  With μ < 1.0, the model stays in the "maximum gradient" regime longer.
  The encoder receives STRONGER, more uniform supervision longer.
  This is arguably BETTER for encoder learning, not worse.


  Effect 3: Weight decay interaction
  ───────────────────────────────────

  The full update: Δw = -μ × lr × (adam_update + wd × w)

  Both the Adam step and weight decay are scaled by μ. This means:
    - Effective weight decay for LM head: μ × lr × wd = 0.5 × 3e-4 × 0.01
    - This is equivalent to wd=0.005 for the LM head at μ=0.5

  The weight decay already has negligible effect on early training
  (wd_simulation.txt proved this: decay/step = 3e-6 × w ≈ 7.2e-8 vs
  gradient/step ≈ 1.5e-5 → ratio 208:1 gradient-dominated).
  Halving the already-negligible decay changes nothing.


  Effect 4: Adam moment dynamics
  ──────────────────────────────

  lr_multiplier does NOT affect moment updates. The kernel computes:
    m_new = β1 × m_old + (1 - β1) × grad
    v_new = β2 × v_old + (1 - β2) × grad²

  These are gradient-driven, not lr-driven. The moments accumulate
  identically whether μ=1.0 or μ=0.5.

  The PARAMETER update uses the moments:
    adam_step = m̂ / (√v̂ + ε)
    Δw = -μ × lr × (adam_step + wd × w)

  So Adam's internal state (learning the gradient distribution) is
  entirely unaffected. Only the step size is scaled.

  From Section 1, attention's upd/param is the FASTEST of all components:

    batch 10: attn=1.12e-03, ffn=8.84e-05 → attn is 12.7× faster than ffn
    batch 60: attn=4.92e-03, ffn=4.62e-04 → attn is 10.6× faster than ffn

  Attention IS learning. It's learning faster than everything else.
  The question is: what is it learning?

  With nearly-uniform initial weights and nearly-identical hidden states,
  attention is learning to produce slightly position-dependent Q,K,V
  projections. But the signal it receives through backprop depends on
  the LM head gradient:

    ∂L/∂Q[t] comes from ∂L/∂h_out[t] = ∂L/∂z[t] × W_lm^T

  If the LM head is in collapse mode (p(36) = 0.5 everywhere):
    ∂L/∂z[t] ≈ (0.5, 0, ..., -0.5, ..., 0) for all t where y_t ≠ 36
    ∂L/∂z[t] ≈ (-0.5, 0, ..., +0.5, ..., 0) for all t where y_t = 36

  These have high absolute magnitude but LOW DIVERSITY across positions.
  The attention layers receive "fix the tok36 problem at every position"
  instead of "learn different patterns at different positions."

  With μ < 1.0, if collapse is prevented:
    ∂L/∂z[t] is position-specific (each position has its own target)
    → attention receives DIVERSE supervision
    → attention can learn position-conditional patterns
    → hidden states diversify → LM head can learn conditional distributions

  This is the virtuous cycle that collapse breaks.

  ┌─────────────────────────────────────────────────────────────────────────┐
  │ MECHANISTIC PREDICTION:                                                │
  │                                                                        │
  │ IF collapse is caused by the LM head outrunning the encoder:           │
  │   → μ < 1.0 prevents collapse                                         │
  │   → Encoder receives diverse gradients                                 │
  │   → Hidden states differentiate by position                            │
  │   → LM head (even at reduced μ) learns conditional distributions      │
  │   → Lower final loss than μ=1.0 despite slower LM head updates        │
  │                                                                        │
  │ IF collapse is caused by hidden state convergence independent of LM:   │
  │   → μ < 1.0 only delays collapse                                      │
  │   → Hidden states still converge to h̄                                │
  │   → Collapse reappears at a later batch                                │
  │                                                                        │
  │ The UpdateTrace data cannot distinguish these two cases.               │
  │ Only running the experiment can.                                       │
  └─────────────────────────────────────────────────────────────────────────┘

9. RISK ANALYSIS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Risk 1: LM head becomes the bottleneck on final loss
  ─────────────────────────────────────────────────────
  Severity: LOW. The LM head is a single linear projection (d_model → V).
  Its capacity is ||W_lm|| × d_model = 768 free parameters per vocab row.
  This converges fast for any reasonable lr. At μ=0.5, it takes ~2× longer
  to converge, but since the encoder is the actual bottleneck for a 12-layer
  transformer, this is unlikely to limit the final loss plateau.

  Evidence: The LM head upd/param (7.27e-4 at B80) is already much larger
  than the embedding (2.21e-4). Even at μ=0.5, the LM head would be at
  3.64e-4 — still faster than the embedding. The LM head is not capacity-
  limited; it's SPEED-limited for the worse.

  Risk 2: Different mode of collapse with a different token
  ─────────────────────────────────────────────────────────
  Severity: MEDIUM. If the collapse mechanism depends on LM head speed,
  slowing it may prevent tok36 collapse. But if the encoder still produces
  uniform h[t], another failure mode could emerge (e.g., all predictions
  become the second most frequent token, or loss stalls higher because
  the LM head can't learn fast enough).

  This is unpredictable from data alone. Requires experiment.

  Risk 3: Wasted training compute
  ───────────────────────────────
  Severity: LOW. The implementation is 3 lines of code: one field in
  ParameterGroup, one multiplication in AdamWKernel, one config assignment.
  A 100-batch test run takes ~2 minutes. If it fails, revert and the cost
  is 2 minutes of GPU time + 10 minutes of coding.

  Risk 4: Interaction with warmup schedule
  ────────────────────────────────────────
  Severity: NONE. The warmup schedule modulates the global lr. lr_multiplier
  modulates the per-group lr. They compose multiplicatively:
    effective_lr = base_lr × warmup_factor(step) × μ
  During warmup, both the encoder and LM head are ramping up. The LM head
  ramps up μ× slower. This is consistent with the intent.

10. WHAT THE MEASURED DATA RULES OUT
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  The UpdateTrace data from session 17720545189054180 factually rules out
  the "attention gradient starvation" hypothesis:

    Raw grad_rms: attn ≈ 18× smaller than ffn (measured via GradTrace)
    Adam upd/param: attn ≈ 10-13× LARGER than ffn (measured via UpdateTrace)

  Adam's per-element v_t normalization COMPLETELY INVERTS the gradient
  size relationship. Attention's small-but-consistent gradients produce
  a small √v̂ denominator, resulting in a LARGER effective update.

  This means:
    ✗ Attn lr_multiplier > 1.0 is NOT needed (attn is already fastest)
    ✗ W_qkv init scaling is NOT needed (the current init+Adam dynamics work)
    ✗ The 18× raw gradient gap is Adam-handled (not a pathology)

  What the data DOES support:
    ✓ The LM head accelerates faster than encoder components
    ✓ The acceleration correlates precisely with collapse onset
    ✓ lr_multiplier < 1.0 for lm would prevent the crossover

  What the data CANNOT prove:
    ? Whether preventing the crossover prevents collapse
    ? Whether the crossover is cause or symptom
    ? What happens beyond batch 80 with μ < 1.0

       float lr_multiplier = 1.0f;    // Per-group learning rate scale

       const float effective_lr = learning_rate * group.lr_multiplier;
       launchAdamWKernel(group, effective_lr, effective_weight_decay, step, stream);

  Total: ~10 lines of functional code + config entry.

12. SUGGESTED TEST MATRIX
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Each run: 200 batches (enough to see collapse at ~B60 or confirm prevention).
  Monitoring: UpdateTrace, COLLAPSE_DETECT, LossStats (already implemented).

  Run 1 (control):  μ = 1.0   — confirm collapse reproduces at B60
  Run 2:            μ = 0.7   — mild slowdown, lm/ffn peaks at 0.93
  Run 3:            μ = 0.5   — moderate slowdown, lm/ffn peaks at 0.67
  Run 4:            μ = 0.3   — aggressive slowdown, lm/ffn peaks at 0.40

  Decision criteria:
    SUCCESS: no COLLAPSE_DETECT trigger through B200, loss continues dropping
    DELAYED: COLLAPSE_DETECT triggers later than B60
    FAILURE: COLLAPSE_DETECT triggers at same batch (~B60)

  If μ=0.5 and μ=0.3 both succeed but μ=0.7 fails:
    → The critical threshold is between 0.7 and 0.5
    → Use μ=0.5 for full training run

  If all three fail (just delayed):
    → Crossover was a symptom, not the cause
    → Need to investigate hidden state convergence mechanism instead

  If μ=0.3 succeeds but causes higher final loss after 500+ batches:
    → Consider warmup schedule for μ (start at 0.3, ramp to 1.0 over N steps)
