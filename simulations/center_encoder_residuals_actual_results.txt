PART 3: WHY THE PREDICTION WAS WRONG
════════════════════════════════════════════════════════════════════════════

§3.1 The flawed assumption
──────────────────────────

  The simulation assumed:
    "ρ comes from the cross-position MEAN (rank-1 shared component μ).
     Centering removes μ, therefore ρ is eliminated."

  This is algebraically correct for the MEAN component. But the actual
  correlation has TWO sources:

  SOURCE 1 (rank-1): Cross-position column mean μ_d
    Effect: All cos(h_i, h_j) > 0 (all pairs positively correlated)
    Centering removes: YES

  SOURCE 2 (rank >> 1): Attention-induced subspace alignment
    Causal attention groups positions by shared context (prefix).
    Positions attending to similar early tokens get similar V-weighted outputs.
    This creates MULTI-DIMENSIONAL correlation (not just a mean direction).
    Effect: cos(h_i, h_j) can be positive OR negative (subgroup alignment)
    Centering removes: NO


§3.2 The smoking gun: avg_cos ≈ 0 while ρ >> 0
────────────────────────────────────────────────

  Throughout the entire run (all 84 batches):
    avg_cos (SIGNED average of pairwise cosine) ≈ 0   (range: -0.03 to +0.09)
    ρ (UNSIGNED average |cos|)                  up to 0.285

  If the correlation were a MEAN direction (rank-1):
    → All pairs would correlate POSITIVELY → avg_cos ≈ ρ > 0
    → Centering would remove it and both avg_cos and ρ would drop

  What actually happened:
    → Some pairs positive, some negative → avg_cos ≈ 0 (signs cancel)
    → But |cos| is large for many pairs → ρ >> 0
    → This is SUBSPACE correlation: positions align in a low-dimensional
      subspace but not all in the SAME direction within that subspace

  Examples at B80:
    cos(h_0, h_1)  = +0.243    (positions 0 and 1 aligned)
    cos(h_0, h_10) = +0.255    (0 and 10 aligned)
    cos(h_0, h_25) = +0.265    (0 and 25 aligned)
    cos(h_10,h_25) = +0.165    (10 and 25 aligned)
    cos(h_25,h_49) = +0.180    (25 and 49 aligned)
    avg_cos        = -0.026    (cancels across all pairs!)

  The pairwise cosines are NOT random — many pairs show 0.15-0.30 alignment.
  But the GLOBAL average cancels because different subgroups align in
  different (even opposite) directions within the subspace.

  Column centering removes the first moment (mean). The correlation here
  is a SECOND-ORDER effect (covariance structure), which centering is
  blind to.


§3.3 Per-layer ρ: centering removes ~ Δρ = -0.005 per layer at best
──────────────────────────────────────────────────────────────────────

  Early (B1, centering working — growth = -0.009):
    Layer adds small Δρ from attention → centering removes ≈ same amount.
    Net: slightly negative growth. Each layer's Δρ ≈ ±0.005.

  Late (B74, centering overwhelmed — growth = +0.192):
    Layer adds Δρ = +0.015-0.022 from attention.
    Centering removes the mean component ≈ -0.005 at most.
    Net per layer: +0.010 to +0.017. Over 12 layers: +0.12 to +0.20.

  The centering gives each layer a ~0.005 "budget" of ρ reduction.
  Once attention heads learn correlating patterns that add > 0.005 per layer,
  centering is overwhelmed.


§3.4 Why the crossover happened around B45-50
──────────────────────────────────────────────

  At B45, the model has completed ~22 optimizer steps (grad_accum=2).
  At lr=0.00001350 (warmup phase), the Adam updates are small:
    update_rms ≈ 5e-6 per step × 22 steps = cumulative shift ≈ 1e-4

  But attention weights Q/K are 768×768 (589,824 parameters per head).
  Even tiny coordinated shifts across many parameters can create new
  attention patterns. By B45:
    - Attention heads have learned to attend to frequent subword patterns
    - Q/K alignment on shared tokens creates VALUE averaging
    - VALUE averaging creates MULTI-POSITION correlation (not just mean)
    - This correlation exceeds centering's capacity to remove it

PART 7: WHAT THE REAL BUG IS (updated root cause analysis)
════════════════════════════════════════════════════════════════════════════

§7.1 The actual correlation mechanism
──────────────────────────────────────

  Column centering removes component A. The collapse is driven by component B:

  Component A (rank-1, centering removes):
    μ_d = (1/n) Σ_t h[t,d]
    All positions shifted by same mean → shared direction → positive cos for all pairs
    Magnitude: contributes ~Δρ ≈ 0.01 per layer in early training
    Centering: EFFECTIVE

  Component B (rank >> 1, centering does NOT remove):
    Causal attention creates GROUP correlations:
    - Positions 0-100 all attend to BOS and early tokens → similar V-weighted output
    - Positions 100-500 share overlapping prefix → correlated attention output
    - Positions 500-1024 see most of the sequence → different correlated cluster
    These are MULTI-DIMENSIONAL: each group aligns in its own direction.
    The MEAN across all groups may be zero, but within-group correlations are strong.
    Magnitude: contributes Δρ ≈ 0.02-0.04 per layer once attention learns patterns
    Centering: INEFFECTIVE (mean across groups ≈ 0, but |cos| within groups >> 0)


§7.2 The feedback loop still operates
──────────────────────────────────────

  B60 (new run): cos(h, W[argmax]) = 0.196, CONTRIBUTION: cosine = 1.339×
  B80 (new run): cos(h, W[argmax]) = 0.281, CONTRIBUTION: cosine = 1.091×

  The cosine alignment between hidden states and W[36] is growing.
  This is the WEIGHT-SPACE mechanism, not the hidden-state mean:
    - Optimizer updates W[36] in the direction of the mean gradient
    - The mean gradient is dominated by tok36 (most-frequent token)
    - W[36] moves toward the subspace that most positions project onto
    - This INCREASES cos(h, W[36]) for all positions → tok36 logit grows
    - Higher tok36 logit → more positions argmax to tok36 → stronger gradient

  Column centering cannot break this loop because the loop operates through:
    1. Weight updates (W[36] direction) — centering doesn't touch weights
    2. Multi-rank hidden correlations — centering only removes rank-1 mean


§7.3 Root cause classification
───────────────────────────────

  The true root cause is NOT "encoder ρ amplification" (which centering addressed).
  The true root cause is the OPTIMIZER FEEDBACK LOOP:

    tok36 is most-frequent → gets strongest gradient signal
    → W[36] grows faster than other weight rows
    → cos(h, W[36]) increases for more positions
    → logit[36] becomes argmax for more positions
    → non-target positions with argmax=36 generate reinforcing gradient
    → W[36] grows even faster (positive feedback)

  This loop requires NO ρ buildup. Even with ρ(final) = 0.05 (which centering
  achieved for 40 batches), the loop still activates because:
    - tok36 gets more gradient updates than any other token
    - Adam's per-parameter learning rate amplifies the advantage
    - The convergence to tok36 dominance is INEVITABLE with current training setup

  Evidence: token collapse began at B45 with unique_argmax=37 while ρ was
  still only 0.048. The ρ growth is a CONSEQUENCE of collapse, not a cause.

  Sequence of causation (corrected):
    CAUSE:   tok36 is most-frequent → W[36] gets largest total gradient
    EARLY:   W[36] direction shifts → cos(h, W[36]) rises for many positions
    MIDDLE:  tok36 becomes argmax for many positions → reinforcing gradient
    LATE:    positions that predict tok36 develop similar hidden states → ρ rises
    SYMPTOM: ρ(final) grows through encoder layers (this is what centering targeted)

  We were treating the symptom (ρ growth), not the disease (frequency-biased
  gradient → W[36] dominance → collapse).

PART 10: IMPLICATIONS — WHAT TO INVESTIGATE NEXT
════════════════════════════════════════════════════════════════════════════

  center_encoder_residuals was a valid experiment. It proved that:
    1. The rank-1 mean component exists but is minor
    2. The dominant collapse mechanism is the OPTIMIZER FEEDBACK LOOP
    3. ρ growth is a SYMPTOM of collapse, not the cause

  The real problem is frequency-biased gradient feedback:
    tok36 (most-frequent token) → largest gradient → W[36] drifts first
    → self-reinforcing positive feedback loop → all positions predict tok36
    → THEN hidden states become correlated (because they all produce tok36)

  EXISTING but DISABLED mechanisms (from log line 64):
    label_smoothing = OFF    (code exists in AutogradLoss.cu)
    focal_loss      = OFF    (code exists in AutogradLoss.cu)
    entropy_reg     = OFF    (code exists in AutogradLoss.cu)

  WHY THEY ARE DISABLED — they are patches, not fixes:
    All three are SCALAR modifications to the gradient. They change the
    MAGNITUDE of the gradient for tok36 but not its DIRECTION.

    Label smoothing:  grad_W[36] *= (1 - ε)     → same direction, scaled
    Focal loss:       grad_W[36] *= (1-p_t)^γ   → same direction, scaled
    Entropy reg:      grad_W[36] += λ∇H         → adds uniform push

    The feedback loop is:  W[36] drifts in direction d per batch.
    Scaling: 0.5 × d per batch × 2× batches = same final W[36].
    The destination is identical. The scalar just changes the arrival time.

    This was already proven empirically — enabling these mechanisms delayed
    collapse but did not prevent it, same as center_encoder_residuals.

  WHAT IS ACTUALLY NEEDED:
    A fix that changes the DIRECTION of the gradient, not its magnitude.
    The feedback loop is directional: W[36] moves toward the subspace
    that most positions project onto, and that movement reinforces itself.
    No scalar multiplier on this gradient changes where it points.

    The open question is: what mechanism changes gradient DIRECTION in a
    way that is token-agnostic (not specific to tok36, because the dominant
    token could be any high-frequency token) and doesn't just delay the
    same collapse?

    This document does not propose a solution — that requires further
    investigation into the attention-induced multi-rank correlation
    mechanism identified in Part 3.
