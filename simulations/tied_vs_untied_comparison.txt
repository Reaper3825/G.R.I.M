     weaker gradients and updates slower, allowing the residual to grow
     more relative to embedding scale.

 SECTION 6: DIAGNOSIS — WHY UNTYING DOESN'T FIX THE COLLAPSE
───────────────────────────────────────────────────────────────────────────────

  Previous hypothesis: Tok36 collapse is caused by tied-weight gradient
  contamination — embedding scatter-add (frequency-proportional) corrupts
  the LM head gradient → space byte row grows → predict space everywhere.

  THIS HYPOTHESIS IS DISPROVEN BY THE DATA.

  Evidence:
  1. Untied session collapses to tok36 at the SAME batch (60)
  2. The collapse severity is nearly identical (67% vs 70% at batch 70)
  3. Encoder gradients (attn, ffn, rmsnorm) are identical in both sessions
  4. Only difference: untied ρ is ~2× lower (delays but doesn't prevent)

  Revised understanding — the collapse has THREE contributors:

  A. ATTENTION GRADIENT STARVATION (primary cause, shared by both)
     ──────────────────────────────────────────────────────────────
     attn gradient rms ≈ 27e-6 at batch 50, vs ffn ≈ 500e-6 (18.5×)
     This means Q/K/V weight updates are 18× slower than FFN weights.
     The attention layer cannot learn to differentiate positions.
     If all positions look the same to attention → all hidden states
     converge → model predicts the most frequent token.

     This is a STRUCTURAL imbalance in the gradient flow, present in
     both tied and untied sessions, and is the primary collapse driver.

  B. FREQUENCY-PROPORTIONAL GRADIENT SIGNAL (secondary, shared by both)
     ──────────────────────────────────────────────────────────────────
     Even in the untied session, the LM HEAD backward pass (dense GEMM)
     uses the centered hidden states as input. When the model starts
     predicting tok36 for many positions (batch 60+), the cross-entropy
     gradient for tok36 row accumulates from many positions, reinforcing
     the tok36 bias. This is a positive feedback loop in BOTH sessions.

     The LM head gradient for row v = Σ_t (p[t,v] - 1{y_t=v}) · h[t]
     When p[t,36] is large for ALL t, gradient points toward "predict
     more tok36" for ALL positions, regardless of tying.

  C. WEIGHT TYING AMPLIFICATION (minor exacerbation, tied only)
     ────────────────────────────────────────────────────────────
     When tied, the embedding scatter-add (873 additions for tok36)
     adds extra directional bias to the shared matrix. This explains
     why tied ρ is 1.6-1.9× higher and tied collapse is slightly faster
     (50% vs 36% at batch 60). But it's the accelerator, not the engine.

  ┌─────────────────────────────────────────────────────────────────────────┐
  │ CONCLUSION: The real problem is ATTENTION GRADIENT STARVATION.         │
  │                                                                       │
  │ When attn gradients are 18× weaker than FFN, the model's only         │
  │ differentiating mechanism (position-dependent attention patterns)      │
  │ cannot learn. The FFN + LM head learn to predict the mode of the      │
  │ distribution (tok36 = space = 10.7% of tokens), while attention       │
  │ remains essentially random.                                           │
  │                                                                       │
  │ Neither tying nor untying addresses this fundamental gradient          │
  │ imbalance in the encoder backbone.                                    │
  └─────────────────────────────────────────────────────────────────────────┘

───────────────────────────────────────────────────────────────────────────────
 SECTION 7: IMPLICATIONS FOR NEXT STEPS
───────────────────────────────────────────────────────────────────────────────

  Since the root cause is attention gradient starvation (not weight tying):

  1. FREQUENCY SCALING on embedding scatter-add is still valid as a
     secondary fix (reduces tied gradient asymmetry), but won't solve
     the collapse by itself — untied proves this.

  2. The primary intervention must increase attention gradient magnitude
     relative to FFN. Possible approaches:

     a) Per-component learning rate: lr_attn = k × lr_base (k > 1)
        Current data shows attn needs about 18× more gradient to match FFN.
        A component-specific lr multiplier of 5-10× for W_q, W_k, W_v
        would bring attention learning rate into the same regime as FFN.

     b) Attention gradient scaling in backward pass:
        Scale dW_q, dW_k, dW_v by a factor before optimizer step.
        Equivalent to (a) but implemented as gradient scaling.

     c) Different optimizer hyperparameters for attention:
        Lower β2 or higher ε for attention parameters could help
        Adam(W) adapt to the smaller gradient scale.

     d) Investigate WHY attn gradients are 18× smaller:
        - Flash Attention backward kernel gradient magnitudes
        - Softmax gradient saturation (if attention is near-uniform,
          ∂softmax/∂z ≈ 0 for all entries → zero gradient flow)
        - ALiBi slope magnitudes (might be too large, causing
          attention to be dominated by positional bias rather than
          learned Q·K similarity)

  3. h_rms growth (16→35× in 70 batches) may be a secondary issue.
     If encoder weights update slowly (because attn is frozen), the
     residual stream grows unchecked. Fixing attention learning should
     indirectly stabilize h_rms.
